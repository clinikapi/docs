# Errors

ClinikAPI uses standard HTTP status codes and returns structured error responses.

## Error Response Format

```json
{
  "error": "Validation Error",
  "code": "VALIDATION_ERROR",
  "requestId": "req_k8f3a7x2",
  "issues": [
    {
      "severity": "error",
      "code": "invalid",
      "diagnostics": "firstName: Invalid input: expected string, received undefined"
    }
  ]
}
```

## HTTP Status Codes

| Status | Meaning |
|--------|---------|
| `400` | Bad Request — malformed JSON or invalid parameters |
| `401` | Unauthorized — missing or invalid API key |
| `403` | Forbidden — key doesn't have required scope |
| `404` | Not Found — resource doesn't exist or belongs to another tenant |
| `409` | Conflict — resource version conflict |
| `402` | Payment Required — billing for the project this key belongs to has stopped |
| `413` | Payload Too Large — request body is larger than 5 MB |
| `422` | Validation Error — request body failed validation |
| `429` | Rate Limited — too many requests for your plan |
| `500` | Internal Error — something went wrong on our end |
| `503` | Service Unavailable — the project is paused or not ready yet, or the store is temporarily unavailable |

## Error Codes

| Code | Description |
|------|-------------|
| `UNAUTHORIZED` | Missing `x-api-key` header |
| `INVALID_KEY_FORMAT` | Key doesn't match `clk_live_*` or `clk_test_*` pattern |
| `INVALID_KEY` | Key not found in the database |
| `KEY_REVOKED` | Key has been revoked |
| `KEY_EXPIRED` | Key has passed its expiration date |
| `INSUFFICIENT_SCOPE` | The key's scopes do not cover this request (`read` for GET, `write` for POST, PATCH and DELETE) |
| `VALIDATION_ERROR` | Request body failed schema validation |
| `INVALID_JSON` | Request body was not valid JSON |
| `PAYLOAD_TOO_LARGE` | Request body is larger than 5 MB (`413`) |
| `METHOD_OVERRIDE_REJECTED` | Request carried an HTTP method-override header |
| `SANDBOX_QUOTA_EXCEEDED` | Monthly sandbox (test-key) allowance used up |
| `RATE_LIMITED` | Plan request limit exceeded |
| `PAYMENT_REQUIRED` | Billing for this project has stopped (`402`). Settle billing in the dashboard; retrying does not help |
| `PROJECT_PAUSED` | This project is paused (`503`). Resume it in the dashboard; retrying does not help |
| `PROJECT_NOT_READY` | This project is not ready yet (`503`), for example while it is being set up or resized. Retry shortly |
| `LIVE_STORE_UNAVAILABLE` | Live data is not available yet (`503`). Every request with a live key returns this until live storage is switched on for your project; use a test key meanwhile. Retrying does not help |
| `NOT_FOUND` | Resource not found |
| `TENANT_TAG_INTEGRITY` | A FHIR PATCH could not be applied safely (`409`); resend it without touching `meta` |
| `INTERNAL_ERROR` | Unexpected server error |

## Project Status

Every key belongs to a project. A project that cannot serve requests refuses its keys before anything is counted: the request does not use any of your quota or rate limit. The answer is an OperationOutcome with a `code` and a `requestId`:

```json
{
  "resourceType": "OperationOutcome",
  "issue": [{ "severity": "error", "code": "forbidden", "diagnostics": "Billing for this project has stopped" }],
  "error": "Payment Required",
  "message": "Billing for this project has stopped",
  "code": "PAYMENT_REQUIRED",
  "requestId": "req_..."
}
```

A project that is being deleted answers like an unknown key (`401 INVALID_KEY`).

## Request Size Limit

Request bodies are limited to **5 MB** on every endpoint, including bulk import and the raw FHIR passthrough. A larger body is refused with `413` and `PAYLOAD_TOO_LARGE` before it is read:

```json
{
  "resourceType": "OperationOutcome",
  "issue": [
    {
      "severity": "error",
      "code": "too-costly",
      "diagnostics": "Request body exceeds the 5 MB limit for this endpoint."
    }
  ],
  "error": "Request body exceeds the 5 MB limit for this endpoint.",
  "code": "PAYLOAD_TOO_LARGE",
  "requestId": "req_k8f3a7x2"
}
```

Split large imports or Bundles into several requests.

## Method Override Is Not Supported

Send the HTTP method you mean. Requests carrying `X-HTTP-Method-Override`,
`X-HTTP-Method` or `X-Method-Override` are rejected with `400` and
`METHOD_OVERRIDE_REJECTED`, whatever the value.

A request whose real method disagrees with the one being executed breaks two
guarantees this API depends on: that a `GET` never modifies data, and that the
audit log records the operation that actually happened. The SDK never sends
these headers.

## SDK Error Handling

The SDK throws typed errors that you can catch:

```ts
import { Clinik } from '@clinikapi/sdk';

const clinik = new Clinik(process.env.CLINIKAPI_SECRET_KEY!);

try {
  const { data } = await clinik.patients.create({
    firstName: 'Jane',
    lastName: 'Doe',
  });
} catch (err) {
  if (err.name === 'ClinikValidationError') {
    console.error('Validation issues:', err.issues);
  } else if (err.name === 'ClinikRateLimitError') {
    console.error('Rate limited. Retry after:', err.retryAfter, 'seconds');
  } else if (err.name === 'ClinikApiError') {
    console.error('API error:', err.code, err.message);
    console.error('Request ID:', err.requestId);
  }
}
```

## Automatic Retries

The SDK automatically retries on `5xx` errors and `429` (rate limit) responses with jittered exponential backoff:

- Default: 2 retries
- Backoff: random jitter up to `min(1000 * 2^attempt, 10000)` ms
- Configurable via `retries` option:

```ts
const clinik = new Clinik(process.env.CLINIKAPI_SECRET_KEY!, {
  retries: 3,      // max retry attempts
  timeout: 15000,  // request timeout in ms
});
```

## Rate Limits

You can see your request counts, errors and latency in the dashboard under [Usage](/dashboard/data/usage), and individual requests, with their request IDs, under [Logs](/dashboard/data/logs).

Test keys have an extra limit of 60 requests per minute per organization; see [Sandbox rules](/dashboard/data/sandbox-rules).

The rate limit is a **per-minute** ceiling on how fast you can call the API. The
window is 60 seconds and rolling — exhaust it and the next minute starts fresh.

| Plan | Requests per minute |
|------|--------------------|
| Sandbox (free) | 60 |
| Starter | 200 |
| Pro | 1,000 |
| Team | 5,000 |
| Enterprise | 10,000 |

It applies to **all** traffic, test and live alike, and is shared across every
key in the organization. Exceeding it returns `429` with code `RATE_LIMITED`.

The current state comes back on every response:

| Header | Description |
|--------|-------------|
| `X-RateLimit-Limit` | Requests allowed per minute on your plan |
| `X-RateLimit-Remaining` | Requests remaining in the current minute |
| `X-RateLimit-Reset` | Seconds until the window resets |

<Note>
The rate limit and the monthly quota are different limits that both return
`429`. The rate limit is about **speed** (per minute); the sandbox quota below is about
**volume** (per month). Check the error `code` to tell them apart:
`RATE_LIMITED` versus `SANDBOX_QUOTA_EXCEEDED`.
</Note>

The SDK exposes these in `meta`:

```ts
const { data, meta } = await clinik.patients.search();
console.log(meta.rateLimitRemaining); // 498
```

## Monthly Sandbox Quota

Only **sandbox** (test-key) traffic has a monthly quota. **Live traffic has no monthly quota on any plan** and is never blocked for volume; it is still counted for [Usage](/dashboard/data/usage), and its speed is limited only by the per-minute rate limit above, which scales with compute.

Every organization has **one shared sandbox pool**: all test keys draw from it. The pool resets on the 1st of each month (UTC).

| Plan | Sandbox requests per month | Live requests per month |
|------|----------------------------|-------------------------|
| Free | 1,000 | Not available |
| Pro | 1,000 | No quota |
| Team | 1,000 | No quota |
| Enterprise | Custom (no cap) | No quota |

Test keys are also limited to **60 requests per minute** per organization, on every plan; see [Sandbox rules](/dashboard/data/sandbox-rules).

Sandbox usage comes back on responses to a test key:

| Header | Description |
|--------|-------------|
| `X-Sandbox-Limit` | Sandbox requests included per month (1,000) |
| `X-Sandbox-Used` | Sandbox requests used this month (org-wide) |
| `X-Sandbox-Remaining` | Sandbox requests left before the cap |

Once the month's 1,000 sandbox requests are used, the next test request returns `429` with code `SANDBOX_QUOTA_EXCEEDED` until the 1st. Nothing extends it, and sandbox traffic is never billed. Use a live key (Pro and Team) to keep working with real data.

```json
{
  "error": "Sandbox quota exceeded",
  "message": "Monthly sandbox quota reached (1,000 test requests).",
  "code": "SANDBOX_QUOTA_EXCEEDED"
}
```

## PHI Sanitization

Error responses never contain Protected Health Information (PHI). Field values are stripped from validation error messages — only field names and constraint descriptions are included.
