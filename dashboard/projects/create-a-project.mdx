# Create a project

## What this is for

A **project** is where your API keys, webhooks and records live. Most teams keep one project per app or environment, for example one for a patient app and one for an internal tool. The **Create a new project** screen is where you name a project and choose how powerful its server should be. Your first project is created for you as part of setting up an organization, using this same screen; later ones use it too.

## Before you start

- You must be an **owner or admin** of the organization. Members cannot create projects, and if you open the address anyway the page simply says it cannot be found.
- Your organization must have no unpaid invoice. While one is overdue, new projects are paused: see [Billing](/dashboard/organizations/billing).
- It helps to know your plan. **Free** projects run on a shared sandbox and can only be the Small size. **Pro** and **Team** projects choose a compute size and can have a failover standby. The compute size is the strength behind the project: more CPU and memory, higher price. **Small** is an isolated store on our shared production infrastructure; **Medium** and larger are a dedicated server.

## Step by step

<Steps>
  <Step title="Open the screen">
    From the project menu in the top bar choose **New project**, or select **New project** on the **Projects** page. For a brand-new organization you arrive here automatically. The page is headed **Create a new project**: "Your project holds its own API keys, webhooks and records."
  </Step>
  <Step title="Check the organization">
    **Organization** shows where the project will be created. Open the menu to switch to another organization you belong to; each shows its plan in brackets.
  </Step>
  <Step title="Name the project">
    Type a **Project name** (placeholder "Project name"). It must be 3 to 60 characters. It starts with a suggestion built from your email, such as "Jane's project". You can rename it later in [Project settings](/dashboard/projects/project-settings).
  </Step>
  <Step title="Look at the region">
    **Region** is fixed and cannot be changed: **United States (us-east-1)**, with the note "Projects are available in the United States only for now."
  </Step>
  <Step title="Choose a compute size">
    Under **Compute size** pick a row. Each shows its size and what it costs:

    | Size | Power | Price when extra |
    |---|---|---|
    | **Small** | 0.5 vCPU · 2 GB RAM | $39/mo |
    | **Medium** | 1 vCPU · 4 GB RAM | $79/mo |
    | **Large** | 2 vCPU · 8 GB RAM | $159/mo |
    | **XL** | 4 vCPU · 16 GB RAM | $319/mo |

    What you can pick depends on your plan:

    - **Free**: only **Small**, shown as **Shared sandbox**. The other sizes carry a **Pro and Team** tag and cannot be selected. A note says "Larger sizes and a production data store come with Pro and Team."
    - **Pro**: the first project includes **Small** (marked **Included**). On a paid plan each row also says what it runs on: **Small** is "Shared production, isolated store", and **Medium** and up are a "Dedicated server". Larger sizes show their monthly price.
    - **Team**: the first project includes **Medium**. **Small** is marked **Below the plan** and cannot be chosen for the first project.
    - Later projects on Pro or Team can use any size, each at its own price.
  </Step>
  <Step title="Decide on failover standby (Pro and Team)">
    **Failover standby** is a second copy of your server that takes over if the first one fails. On **Team** it is on and included ("Included with Team."). On **Pro** it is a switch, off by default: "A second copy that takes over if the first fails. Priced at the compute size."
  </Step>
  <Step title="Read the cost line">
    At the bottom left, a paid plan shows either **Additional costs** with an amount per month, or "Included in your plan." (first project) or "No additional cost.". The first project is included at the size your plan comes with, so only a larger size, or a Pro standby, is extra. Every later project is billed at its own size.
  </Step>
  <Step title="Select Create new project">
    The button reads **Creating…** while it works. If there are additional costs, a box titled **Confirm compute costs** opens first: "This project's compute adds the amount a month to your bill once the server is ready, whatever its usage. By continuing you agree to the additional cost." Select **I understand** to go ahead, or close the box to change your choices. **Cancel** takes you back without creating anything.
  </Step>
</Steps>

On success you go to the setup screen, which creates a **test key** and shows it once. That part is described in [Create an organization](/dashboard/organizations/create-an-organization#what-happens-next).

## What you'll see

- A notice above the buttons: "Production projects are rolling out. Your project starts on the sandbox, with test keys and synthetic data, and moves to its production store when it is ready." On a paid plan it adds "Compute is billed by the hour, and only once the server is ready." Both messages say the same thing: nothing is billed for compute until the project is on its production store, and from then it is billed by the hour at the monthly price shown.
- If this is your organization's first project and it still has the automatic **Default project**, setting it up renames that project (or replaces it with a new one if it is untouched) instead of adding a second. Replacing it can only be done by the owner.

## Common questions

<AccordionGroup>
  <Accordion title="What is the difference between the sandbox and a production data store?">
    The sandbox is a shared practice area with invented data and test keys. A production data store is where real patient data goes, with live keys, on Pro and Team. On Pro it is your own isolated store on our shared production infrastructure; dedicated servers start at the Medium size, included on Team. New projects start on the sandbox and move across when their store is ready.
  </Accordion>
  <Accordion title="Can I change the size later?">
    Yes. The size on this screen is a starting point ("You can change this later"); see [Compute and disk](/dashboard/projects/compute-and-disk).
  </Accordion>
  <Accordion title="Why can I not pick Medium or Large on Free?">
    Free is a shared sandbox, so only Small applies. Upgrade the organization from [Billing](/dashboard/organizations/billing) to unlock the others.
  </Accordion>
  <Accordion title="Why is Region greyed out?">
    Free and Pro projects are in the United States, so there is nothing to choose. Team and Enterprise can ask us for another region; regions open on request, and none other is open yet.
  </Accordion>
  <Accordion title="Is anything deleted if I make a mistake?">
    No. You can rename a project in its settings. Deleting one is a separate, owner-only action with a confirmation: see [Project settings](/dashboard/projects/project-settings).
  </Accordion>
</AccordionGroup>

## Troubleshooting

| What you see | What to do |
|---|---|
| "Give the project a name." | Type a **Project name**. |
| "The name must be at least 3 characters." / "The name must be 60 characters or fewer." | Adjust the length. |
| "The name cannot contain control characters." | Remove unusual invisible characters, for example from a paste. |
| "That compute size is not available on this plan." | Pick a size your plan allows, or change plan in [Billing](/dashboard/organizations/billing). |
| "Your organization has an unpaid invoice. Pay it in Billing to create new projects." | Pay the invoice on the **Billing** page, then try again. |
| "Only the organization owner can set up the first project." | Ask the owner to complete this step. |
| The page says it cannot be found | You are not an owner or admin of that organization, or the address is wrong. |
| A message in red above the buttons with another reason | Read it; it names what the system refused. Try again, then contact support if it repeats. |
